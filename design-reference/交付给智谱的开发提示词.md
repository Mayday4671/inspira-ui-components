## 0. 你的身份、工作方式与最终目标

你现在是高级 Vue 3 / TypeScript 前端工程师、设计系统工程师与严格的视觉验收负责人。你要在**我现有的 inspira-ui-components 仓库上增量修改**，不是重写一个新的空壳站点。

原项目的目标是：将 Inspira UI 的精美动画组件封装成**类似 Element Plus 的 npm 安装、全局注册 / 按需导入、统一类型与 API 的组件库**；文档站负责真实演示组件、指导使用，不是用一些漂亮静态卡片冒充组件库。

用户给了你高保真设计基准：

- `index.html`：这次重设计的**唯一页面布局与视觉基准**，包含首页、组件目录、快速开始、组件详情、主题定制、响应式视图及部分交互。
- `截图-首页-1440.png`、`截图-组件总览-1440.png`、`截图-组件详情-1440.png`、`截图-快速开始-1440.png`、`截图-组件详情-390.png`：视觉对照基准。
- `设计规范与验收清单.md`：设计 Token、布局、响应式、滚动条规则、功能与工程验收。

**核心原则：外观对照原型，行为与数据对照真实源码，最终结果需要两者同时通过。**

### 禁止行为（必须遵守）

1. 禁止擅自换风格、换配色、发明另一套 Landing Page；不要把设计简化成几个随便摆放的卡片。
2. 禁止把现有组件改成截图、Gif、canvas 静态贴图或只有 Hover CSS 的伪组件。**真正的组件演示必须导入真实 Vue 组件并可操作**。
3. 禁止破坏现有 npm 包、组件导出、名称、Props、Events、插槽、已有动画及公开 API。必要迁移需说明前后兼容关系。
4. 禁止为了“22 个”这个旧页面数字虚构新组件、虚构类型或乱写 API；最终组件清单来自源码注册表或实际导出。
5. 禁止用 `height:100vh; overflow:auto` 在 body、sidebar、main、preview、右侧目录上反复嵌套滚动容器；页面只能有一条可见的纵向主滚动条。
6. 禁止在 1440 / 1920 桌面端让正文挤成窄柱；禁止在 390px 宽度上强塞三栏布局；禁止任何横向页面溢出。
7. 禁止只改首页而漏掉目录、快速开始、详情及主题页面；禁止功能入口只有外观没响应。
8. 禁止在未看实际截图、未测交互的情况下声称“已完美复现”“全部完成”。
9. 不要因为某一步出现视觉瑕疵就停止等待我逐项指挥：先自行修正并复查；只有真正阻断性的源码/依赖问题再向我报告。

## 2. 视觉设计基准（所有页面统一）

原型是“克制的专业开发者文档站”，不是大面积荧光渐变广告页：

| 类别 | 必须遵循的基准 |
|---|---|
| 默认配色 | 亮色优先；主背景 `#f8f9fc`、卡片 `#fff`、文字 `#202535`、强调色 `#6558e8`、边框 `#e8ebf1` |
| 深色模式 | 同一组件结构的完整深色映射；不是把页面反色 |
| 字体 | 系统无衬线优先，中文可读；统一 11/12/13/14/16/21/32px 字阶 |
| 圆角 | 小控件 8–10px、卡片 12–16px，禁止每处随意变化 |
| 阴影 | 轻微阴影，仅在 hover、浮层或重点展示中使用 |
| 顶栏 | 桌面高 68px，Logo + 一级导航 + 搜索 + 主题 + 版本入口；吸顶 |
| 左栏 | 桌面宽约 249px，分组、当前条目突出、支持折叠；超出视口时允许滚动但**不出现可见第二滚动条** |
| 正文 | 宽度随桌面增加而合理铺开，保持最大阅读宽度与合理左右间距 |
| 右侧 TOC | 详情和指南页约 175px；宽度不足自动隐藏；不设独立滚动容器 |
| 首页 | 左文案 + 右侧真实预览，三项价值说明，精选组件展示栅格 |
| 组件总览 | 搜索框 + 类别筛选 + **真实动效预览卡片**，绝不使用纯蓝色链接列表 |
| 组件详情 | 标题 / 状态标签 → 实时预览 → 参数操作区 → 代码 → API 表 → 无障碍说明 |
| 代码 | 与亮色内容有层次的深色代码块；复制功能真实可用；内容是实际运行代码 |

不要把所有内容放进巨大的卡片里，也不要为每个小组件创建新的滚动区域。最重要的是**信息密度适中，演示区突出，页面结构清楚，滚动自然**。

## 3. 分阶段执行：每完成一阶段就截图对照、自查修复，再进入下一阶段

### 阶段 A｜基础设计系统与页面骨架

- 从原型提取 Token（CSS 变量 / SCSS / ThemeProvider，与项目现有技术栈保持一致）。
- 做好顶部导航、全局容器、桌面侧边栏、右侧目录、移动端抽屉。
- 统一字号、按钮、标签、卡片、代码区、表格、空状态、间距、圆角。
- 路由必须支持首页、指南、组件总览、每个真实组件详情、主题页。
- 搜索要能用鼠标及 Ctrl+K 打开，Escape 关闭，检索实际组件与文档。

**A 阶段验收**：1920×1080、1440×900、390×844 的壳层截图与原型布局相符；浏览器无 console error；`document.documentElement.scrollWidth <= window.innerWidth`；页面只有一条可见纵向滚动条。未达标先修。

### 阶段 B｜首页

- 严格照 `index.html#/home`：浅色高质感、hero 左侧清晰两行大标题、右侧简约 Live Preview 展示、主次按钮、三项价值说明。
- 下方“精选组件”是 3 列桌面栅格，展示真的组件动效；组件名、用途、跳转对应真实详情。
- 首页真实按钮可点击，无悬空路由。优先保证首屏一致，不随意加入堆叠的数字统计。

**B 阶段验收**：桌面首屏布局与参考对齐，hero 不出现孤立单字换行，动效流畅，卡片无视觉错位，移动端能自然变成单列。

### 阶段 C｜组件总览

- 按 `index.html#/components` 实现：标题、描述、搜索输入、类别过滤、清晰卡片目录。
- 每张卡片前半区域是真实组件预览，后半区域为组件名、简短说明与点击入口。
- 数量/分类必须从仓库实际导出生成或基于真实注册数据统一维护，不能写死“22”后卡片却只有 20 个。
- 搜索同时支持英文组件名、中文别称、关键词；空结果提供清空操作。
- 卡片等高、合理留白、桌面 3 列；适中宽度 2 列；窄屏变成清晰易读的列表。

**C 阶段验收**：每个可见组件点进去都能找到对应的真实文档页面；筛选与搜索正确；无重名、无错链、无虚构内容。

### 阶段 D｜组件详情模板与全部组件适配

以 `ShimmerButton` 作为第一个**黄金模板**，先达到截图质量后再复用给其他组件。不要一开始复制 22 份不合格页面。

详情页必须包含：

1. 面包屑、英文组件名、中文用途、真实类别标签。
2. “实时演示”区域：通过原本真正的 Vue 组件实现，不是模拟按钮文字。
3. 如果真实 API 支持 `text / size / loading / disabled`，做可调控件，预览与代码双向保持一致；不支持的 Props 不得强行添加。
4. 复制完整代码、安装提示、全局/按需用法、真实 API 表、事件/插槽（有则写）、交互与无障碍说明。
5. 不同组件保留各自实际 demo（翻转卡片真的翻转，数字真的递增，Dialog 真的弹出、关闭并管理焦点，Marquee 真的滚动等）。
6. 源码演示与真实 API 保持一致，不能出现文档可以复制却无法编译的代码。

**D 阶段验收**：先完成并比对 `ShimmerButton`，再全部组件逐项补齐；每项至少验证默认态、可用的交互态、深色态、窄屏态；每个真实 Props 的默认值与类型来自源码。

### 阶段 E｜快速开始、主题与开发者体验

- 快速开始按照“安装 → 按需引入 → 全局注册 → 验证排错”的阅读顺序。提供 pnpm/npm/yarn 切换、有效代码复制。
- 组件是否需要 `app.use`、必须单独引入 CSS、实际包名是什么，只能以当前产物验证结果为准。
- 主题页面提供亮色 / 暗色实时切换与 CSS Token，保存用户选择。
- 维持适当的动效，不得因为酷炫而破坏正文可读性；支持 `prefers-reduced-motion`。

**E 阶段验收**：把文档拷到一个全新的 Vue 3 + Vite 测试项目进行真实安装、导入、构建，保证文档代码可运行。

### 阶段 F｜工程校验、截图回归与最终交付

必须执行可用的 lint、typecheck、unit tests、build；在有现成 e2e 工具时补充关键交互用例。

用 Chromium/Playwright 实际打开项目，**不是只看代码估算效果**。以下 3 组分辨率逐页截图：

- 桌面：1920×1080、1440×900；
- 移动：390×844；必要时补查 768 / 1024 宽度。

检查首页、目录、快速开始、ShimmerButton 详情、另一种卡片组件详情、主题页；在 390px 下打开移动导航确认其能关闭及跳转。验证 Ctrl+K 搜索、筛选、复制、主题、参数修改、弹窗操作、锚点跳转。

量化硬性条件：

```js
const viewport = window.innerWidth;
const htmlWidth = document.documentElement.scrollWidth;
if (htmlWidth > viewport) throw Error(`页面出现横向溢出：${htmlWidth} > ${viewport}`);

const visibleScrollContainers = [...document.querySelectorAll('body *')]
  .filter(el => {
    const s = getComputedStyle(el);
    return /auto|scroll/.test(s.overflowY) && el.scrollHeight > el.clientHeight + 2;
  });
// 只允许隐藏滚动条的折叠侧栏、必要时的临时浮层内部滚动。
// 不允许文档主区、组件预览区、右侧目录成为第二条可见纵向滚动条。
```

**注意**：不能靠全局 `overflow:hidden` 把真正超出边界的内容裁掉，必须找到元素、修好布局。

浏览器截图与参考对照：主要区域的栏宽、对齐、字号、按钮大小、卡片大小、间距及配色尽量保持同一设计系统。关键区域的偏差应控制在肉眼可接受范围内；出现明显偏移必须修复，而不是用“风格接近”敷衍。

## 4. 封装工程不能因“改页面”而退化

- 保持 Vue 3 + TypeScript 的现有架构，尽量不强制消费者安装 Tailwind；如果确实有依赖，明确列出并避免污染消费者全局样式。
- 确认打包导出 `main/module/types/exports`、ESM 兼容、样式入口与 `sideEffects`，并在实际 Vite 使用环境测试 tree-shaking。
- 样式变量及类名建议前缀 `iu-`，避免影响用户项目里的 Element Plus 或其他组件。
- 动画依赖、浏览器兼容、键盘焦点与 SSR（如宣称支持）均须真实验证，不要只在本机开发模式正常。
- 如果复用了上游 Inspira UI 代码，保留许可、署名与版权信息；明确“封装库”并非上游官方 npm 包。
- 动画质量优先保真：禁止为了视觉截图而移除原本的 motion、过渡、事件处理。
